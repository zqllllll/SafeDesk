> **注**：平均 Token 包含 Agent 调用和 Runtime 调用（Contract Builder、Recovery、Summarizer 等），因此与成功/失败任务 Token 的加权平均值存在差异。

### 关键发现

1. **TGC 提升 19.66pp**：从 41.73% 提升到 61.39%，增幅 47.1%
2. **假完成率大幅下降**：从 46.79% 降至 16.61%，相对下降 64.5%
3. **Max-Turn 率下降 53.8%**：从 21.82% 降至 10.07%
4. **Invalid Call 下降 78.4%**：Schema Guard 和 Effect Preflight 极大减少了参数错误
5. **Token 节省 40.6%**：Context Manager 的优先级分配和结果投影显著降低了每轮 Token 消耗
6. **重复写操作下降 80.9%**：Effect Ledger 的幂等键预检有效防止了重复副作用

## 6. τ²-Bench 核心指标

**Benchmark**：τ²-bench  
**任务数**：278（Airline 50 + Retail 114 + Telecom 114）  
**Agent 模型**：GLM-5（关闭 Thinking）  
**User Simulator / Judge 模型**：DeepSeek V4 Flash（关闭 Thinking）

### 评估协议说明

- **pass@1**：任务独立运行 1 次，通过即算通过。pass@1 = 单次运行通过率。
- **pass@4**：任务独立运行 4 次（4 次完整从头执行），**全部 4 次都必须通过**才算通过。因此 pass@4 始终 ≤ pass@1。
- **DB match rate**：所有任务中 DB 状态与评估器目标一致的占比（与最终通过率口径不同，DB 不匹配的任务仍可能通过通信等其他评估组件）。
- **DB mismatch（失败分类）**：仅统计最终失败任务中，主失败原因为 DB 不匹配的数量。
