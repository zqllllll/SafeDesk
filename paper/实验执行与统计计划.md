# SafeDesk 实验执行与统计计划

## 1. 目标

本计划用于回答三个问题：

1. 在模型、提示、工具集合和预算一致时，SafeDesk 是否提高任务与场景完成率？
2. SafeDesk 是否减少假完成、非法调用、重复写入、停滞和 Token 消耗？
3. 四个核心模块分别贡献了什么，是否存在准确率与治理成本之间的权衡？

实验结果必须来自实际运行，不使用人工构造成功标签，不以 evaluator 子测试通过率替代任务完成率。

## 2. 冻结条件

### 2.1 AppWorld 主实验

| 项目 | 冻结值 |
| --- | --- |
| 模型 | `qwen3-14b` 的同一 API 版本 |
| 思考模式 | 关闭 |
| 温度 | 0；如服务端不保证确定性则完整记录 seed/请求参数 |
| 数据集 | `test_normal` 168 项；`test_challenge` 417 项 |
| 工具模式 | function calling |
| API 预测器 | 基线与 SafeDesk 使用同一预测模型、提示和上限 |
| 最大轮数 | 50 |
| 状态保存 | 每个执行步骤后保存；evaluation 前断言持久化成功 |
| 运行顺序 | 先 train/dev 调试，配置冻结后再运行 test；不得根据 test 结果调参 |
| 并行调用 | 两组使用相同协议；写操作按状态依赖串行化 |

基线允许原 runner 的正常功能，但不得包含 SafeDesk 的证据门、效果账本、类型化恢复或上下文预算。SafeDesk 组除四模块外不得改变模型、任务、API 预测器、完成上限和评测器。

### 2.2 τ² 主实验

冻结 airline、retail、telecom-base 的任务 ID 清单。Agent 使用同一 Qwen3-14B no-thinking 配置；用户模拟器与 judge 的模型、提示和采样参数在两组间完全一致。Token 必须按 `agent`、`user`、`judge` 分角色记录，主文报告 agent Token，同时在附录给出系统总 Token。

## 4. 指标

### 4.1 主要效果指标

- **TGC**：成功任务数 / 有效任务数。
- **SGC**：同一场景的全部变体均成功的场景数 / 完整场景数。
- **τ² pass rate / pass^k**：分别衡量单次成功和多次运行可靠性。

### 4.2 可靠性与安全指标

- 假完成率：Agent 声明完成但 evaluator 失败，并经 completion evidence 审核确认。
- Max-Turn Rate：达到最大轮数的有效任务占比。
- Invalid Call Rate：非法模型调用数 / 模型提出的全部工具调用数。
- Out-of-Schema Rate：不在当前 active schema 的调用数 / 模型提出调用数。
- 重复写操作率：重复写调用数 / 执行写调用数。
- 非预期副作用：任务合同之外、经状态差异确认的写效果数量。
- 验证覆盖率：已验证 required effects / required effects。
- Recovery 成功率：修复后恢复有效进展的 recovery / 已触发 recovery。

“任务失败且通过部分 evaluator test”只能记为部分完成候选。只有当目标级检查确认至少一个非平凡子目标完成时，才写 `partial_completion=true`。

### 4.3 效率指标

- Agent 输入、输出、总 Token；预测器 Token 单列。
- 平均数、中位数、P95 与最大值，避免均值掩盖长尾。
- 工具调用数、轮数、单任务时长与运行成本。
- SafeDesk 自身附加调用、验证调用、上下文构建耗时。

## 5. 统计检验

1. TGC、SGC 和二元可靠性指标报告 Wilson 95% 置信区间。
2. 同一任务的 baseline/SafeDesk 成败使用 McNemar 检验，并报告配对差异。
3. Token、轮数和调用数使用任务级配对 bootstrap（10,000 次）估计均值与中位数差异的 95% 区间。
4. 多个消融比较使用 Holm 校正，并同时报告原始效应量，不仅报告 p 值。
5. τ² 每任务至少运行 3 次；资源允许时使用 8 次以报告 pass^8。模型服务不支持 seed 时，记录请求时间、模型版本和采样配置。

## 6. 断点续跑和数据质量

- 每个任务使用唯一 `run_id`，并由 `experiment_id + task_id + trial_id + config_hash` 唯一确定。
- 每项任务原子写入结果文件；汇总只读取完成且 schema 校验通过的任务。
- 失败分为 model、tool、evaluator、sandbox、timeout、rate-limit、provider 和 persistence。
- 基础设施错误不计入模型分母，但必须报告数量并用同配置重跑；不得只重跑模型失败任务。
- evaluation 前验证最终数据库快照与持久化标志；状态保存失败直接标为 infra error。
- 每次汇总保存配置、代码提交哈希、任务清单哈希、模型响应中的 model/version 字段和数据清单。

## 7. 假完成与副作用复核

对所有“调用完成但任务失败”的轨迹进行自动初筛：

1. Completion Gate 当时的 Task State；
2. required effect 是否有写入证据；
3. 是否有 post-action readback；
4. evaluator 失败项与最终数据库差异；
5. 是否存在任务合同外写入。

自动判定置信度不足时进入双人独立复核。分歧由第三人裁决，并保存匿名化判定理由。报告 Cohen's kappa 或 Krippendorff's alpha。

## 8. 投稿准入

只有满足以下条件才能把 SafeDesk 的效果写入摘要和结论：

- E2-E5 完成且配置一致；
- A0/A4 至少完成一个完整测试集；
- 主要指标由原始任务级结果重算一致；
- 无未解释的状态保存、时间计量或编码故障；
- `claims_registry.csv` 中相应声明从 `pending` 改为 `measured`；
- 论文表格、数据包与代码提交哈希互相对应。
