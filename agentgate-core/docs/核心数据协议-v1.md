# AgentGate 核心数据协议 v1

本文说明 `agentgate-core` 在协议版本 `1.0` 中固定的数据边界。它描述数据的结构和不变量，不实现状态推进、工具执行、验证或恢复策略。

## 设计原则

1. **严格输入**：所有模型拒绝未知字段，避免字段拼写错误或版本漂移被静默接受。
2. **不可变对象**：模型创建后不能原地修改。状态变化必须在后续 Typed State Store 中通过事件生成新版本。
3. **显式版本**：所有可持久化顶层对象都携带 `schema_version="1.0"`。
4. **可追溯事实**：已验证证据和已验证副作用必须引用真实的 Verification 记录。
5. **写操作可控**：写 Action 必须声明预期副作用和幂等键；读 Action 不得声明副作用。
6. **JSON 可交换**：持久化 Payload 只接受 JSON 兼容值，便于 Trace 回放、跨进程传输和离线分析。
7. **时间可比较**：所有时间字段必须包含时区。

## 核心对象

### TaskContract 与 TaskState

`TaskContract` 保存原始指令、规范化目标、子目标依赖、约束和完成条件，是任务目标的稳定来源。

`TaskState` 保存某个版本的运行状态。它会拒绝不存在的活动子目标、仍被标记为活动的终态子目标，以及完成阶段仍存在活动子目标等结构矛盾。合法状态迁移将在下一阶段由 Reducer 负责，模型本身不猜测如何迁移。

### ActionIR

`ActionIR` 是模型工具调用进入治理层后的统一表示。它明确区分读写，记录工具 Schema 版本、来源轮次、依赖 Action、所需证据、风险和预期副作用。

写操作必须同时具备：

- 非空 `idempotency_key`；
- 至少一个 `expected_effects`；
- 可定位的工具、操作和 Schema 版本。

这只保证 Action 可治理，不表示它已获准执行。Schema Guard、Policy Gate 和 Dependency Scheduler 会在后续阶段作出决定。

### EvidenceItem、EffectRecord 与 VerificationResult

`EvidenceItem` 区分观察、推断、验证、冲突、过期和撤销状态。`VERIFIED` 证据必须引用至少一个 Verification。

`EffectRecord` 记录写操作从计划、保留、执行到验证或失败的生命周期。`VERIFIED` Effect 必须包含实际变化和 Verification ID；尚未执行的 Effect 不得提前携带实际变化。

`VerificationResult` 同时保存预期状态和观察状态。结果为 `MISMATCH` 时必须给出字段差异或非预期副作用；结果为 `ERROR` 时必须给出错误信息。

### FailureRecord

`FailureRecord` 使用稳定的失败分类和责任层，记录重试性、证据、尝试次数与剩余恢复预算。恢复预算耗尽时剩余预算必须为零；标记已解决时必须引用解决事件。

### ContextPack

`ContextPack` 是 Context Manager 向单次模型调用提供的结构化上下文快照。它保留 P0-P4 优先级、事实来源 Event、Token 估算和软硬预算。

`budget_status` 不能由调用方随意填写，必须与 `estimated_tokens`、`soft_token_limit` 和 `hard_token_limit` 的关系一致。该约束防止监控数据显示“预算内”，实际却已经超限。

### TraceEvent

`TraceEvent` 是追加式审计协议，包含唯一 Event、Task、Run、有序序号、轮次、时间、事件类型、Actor、父事件、关联 ID、状态版本、JSON Payload 和脱敏元数据。

`sequence_number` 用于同一 Run 内的确定性排序，`parent_event_id` 表达因果关系，`correlation_id` 关联一次模型响应、工具调用、验证和恢复链。Event 不得把自己设为父事件。

Trace 模型只固定单事件结构。跨事件连续递增、父事件存在性、写操作 Trace 持久化失败时 Fail Closed 等规则，将由 Trace Recorder 和 Store 实现。

### ToolCatalogSnapshot

`ToolCatalogSnapshot` 固定某次运行实际可用的工具集合。每个 Tool Entry 明确保存输入/输出 Schema、读写性质、风险、副作用类型、资源类型、证据与政策要求、工具依赖、验证策略和幂等策略。

写工具必须显式声明资源、副作用、验证和幂等策略；读工具不得声明副作用或幂等策略。Schema Version 根据规范化 JSON Schema 计算 SHA-256，使 Trace 可以确认模型调用时实际绑定的是哪一版工具协议。

## JSON Schema

公开顶层对象的 Draft 2020-12 Schema 位于：

```text
agentgate_core/schemas/v1/*.schema.json
```

每个 Schema 都有稳定的 `$id` 和固定的协议版本。测试会重新从 Pydantic 模型生成 Schema 并与落盘文件逐字比较；任何模型改动都必须显式重新生成并接受协议差异，不能让代码与对外 Schema 分叉。

## 本阶段不包含的能力

- Task Reducer 和合法状态迁移；
- Typed State Store、乐观并发和 Checkpoint；
- Tool Schema Guard、Policy Gate 和 Dependency Scheduler；
- 工具执行、写后回读和 Completion Gate；
- Failure Classifier 与 Typed Recovery；
- Context 压缩算法和 Trace Recorder 持久化。

这些能力会使用本协议作为输入输出边界，在后续开发步骤中逐项实现和测试。
