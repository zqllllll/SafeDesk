# SafeDesk 四模块运行编排说明

## 1. 统一装配

`assemble_agentgate()` 是 runner 的组合根。调用方注入 Run ID、Typed State Store、Trace Recorder、Tool Catalog、Feature Config、Policy Rule、Verifier 和 Result Projector，工厂返回 `AgentGateAssembly`。

Assembly 明确暴露：

- `SafeDeskOrchestrator`；
- `AgentGateRuntimeSession` 和 Coordinator；
- Active Tool Set Manager 和 Dynamic Tool Resolver；
- Verifier Registry 和 Guarded Effect Ledger；
- Recovery Controller、Progress Tracker 和 Stagnation Detector；
- Context Builder。

Runner 不应自行复制模块状态机。

## 2. 标准生命周期

### 2.1 任务初始化

1. 创建 TaskContract 和初始 TaskState；
2. 初始化 Active Tool Set；
3. 注册 adapter 的 Policy Rule、Verifier 和 Tool Result Projector；
4. 保存配置哈希、Catalog 版本和运行标识。

### 2.2 模型调用前

调用 `orchestrator.before_model()`。Context Manager 从当前持久化状态生成 ContextPack；超过硬预算或不变量失败时不得调用模型。

### 2.3 模型提出工具后

调用 `orchestrator.guard_tool_batch()`，并传入本轮全部 Tool Call。返回结果与输入严格同序、同数量。

- `should_execute=true`：runner 调用 `mark_tool_started()` 后执行工具；
- `should_execute=false`：runner 把 `tool_result_status` 按原 `tool_call_id` 返回模型；
- `requires_state_refresh=true`：首个写操作结束后重建 ContextPack，再允许模型规划后续动作。

不得只执行第一个调用并静默丢弃其余调用。

### 2.4 工具执行后

runner 构造 `ToolExecutionReport` 并调用 `after_tool()`：

- 所有已开始调用记录匹配的 `TOOL_FINISHED`；
- 读取结果进入 Evidence Board，初始为 OBSERVED；
- 写 Effect 进入 APPLIED_UNVERIFIED 或 FAILED；
- 有 Verifier 时执行公开环境回读；
- Verified Evidence、Effect、Failure 和 Subgoal 状态写入 State Store。

没有 Verifier profile 时，Effect 保持未验证，Completion Gate 不允许把任务判为完成。

### 2.5 进展和恢复

每轮关键动作前调用 `capture_progress()`，执行后调用 `assess_progress()`。如果停滞或发生类型化失败，调用 `recover()` 生成计划；执行计划后调用 `finish_recovery()`，由真实进展和 Verification 决定是否恢复成功。

### 2.6 结束请求

自然语言结束使用 `request_completion()`；完成工具由 Coordinator 的 Completion Gate 拦截。只有 required subgoal、completion condition、Effect、Failure、确认和副作用检查全部满足时，ENFORCE 模式才允许完成。最终回复还要经过 Response Grounding Gate。

## 3. Trace 配对规则

- 每个模型 Tool Call 必须有一个 GuardedToolCall；
- 每个未执行调用必须有 `TOOL_NOT_EXECUTED` 和结构化 Tool Result；
- 每个已执行调用必须有同 correlation ID 的 `TOOL_STARTED` 和 `TOOL_FINISHED`；
- Effect 状态变化使用 `EFFECT_STATUS_CHANGED`，不得伪装成工具完成；
- Schema、Policy、Completion、Recovery 和 Context 决策均写入独立事件。

这些规则保证 Trace Replay 可以识别缺失结果、重复结束和未闭合调用。

## 4. Feature Mode

Coordinator 支持 `OFF`、`SHADOW` 和 `ENFORCE`：

- OFF：不调用该 feature 的阶段逻辑；
- SHADOW：记录 proposed outcome，但 effective outcome 保持 ALLOW；
- ENFORCE：应用 proposed outcome。

`SafeDeskOrchestrator` 是四模块集成执行路径。Baseline runner 若不启用 SafeDesk，应继续使用原执行路径；不要把 OFF 模式误当成“运行完整 orchestrator 后再忽略部分结果”。消融实验则通过 Feature Config 在统一路径中逐模块切换。

## 5. Checkpoint 恢复

Task/Evidence/Effect/Failure/Verification 由 Typed State Store 持久化。Active Tool Set 和 Recovery Budget 提供显式 `restore()`：

1. 恢复时校验 Catalog、Schema 和 Recovery 配置版本；
2. 从 checkpoint 或 Trace 恢复运行状态；
3. 重新读取环境中的未验证/未知 Effect；
4. 重建 ContextPack；
5. 不直接复用中断前的模型计划。

## 6. 当前交付边界

本轮完成四个核心模块及统一编排的代码实现。AppWorld 具体资源的 Verifier profile、DeerFlow middleware hook、τ² Conversation State adapter 和正式 benchmark 验证属于后续接入与验收阶段，不应混入核心状态机。
